# Motion-Graphics Studio · помощник для Claude Code

@../../AGENTS.md

Это рабочее пространство для создания **моушн-графики кодом**: Claude Code пишет анимацию,
а **Remotion** рендерит её в настоящий видеофайл — титры, нижние трети, оверлеи, интро,
переходы. На выходе — клип (в т.ч. **с прозрачным фоном**), который кладётся в любой
видеоредактор (Premiere, Final Cut, DaVinci, CapCut, After Effects).

Этот файл — инструкция для тебя, Claude Code. Следуй ему при работе в этом проекте.

---

## ⭐ Начало задачи по моушн-графике

Используй этот инструмент только тогда, когда пользователь просит создать, изменить
или заново отрендерить анимацию. Не устанавливай зависимости, не запускай Studio и
не открывай браузер при обычной работе над PWA.

В начале задачи по моушн-графике выполни по порядку:

1. **Проверь готовую настройку** (см. раздел 2). Не переинициализируй проект и не
   обновляй зависимости без отдельной необходимости.
2. **Запусти Remotion Studio** (`npm run studio`) в фоне, чтобы у пользователя открылся
   визуальный интерфейс в браузере (обычно `http://localhost:3000`).
3. **Сообщи пользователю** примерно так:
   > «Я открыл в браузере интерфейс Remotion — там ты можешь вживую видеть, как рождается
   > анимация, и при желании поправить параметры. Делать там ничего не обязательно, это
   > просто для наглядности и контроля — вся работа идёт через меня.»
4. Продолжай выполнять уже сформулированный запрос. Уточняй только действительно
   недостающие параметры.

Смысл: пользователь с первого касания видит, что Claude работает не «вслепую» — рядом
открыт живой интерфейс, где всё видно и можно вмешаться.

## 0. Как со мной работать (для пользователя)

Пользователь описывает желаемую графику **обычными словами** — например:
«сделай нижнюю треть с именем и должностью», «интро с заголовком», «анимация лайка».
Терминал и код трогать не нужно — все команды выполняет Claude Code.
Внутри `ридэй` сначала используй его дизайн-систему и существующую визуальную
логику. Спрашивай пользователя только о параметрах, которых нет в запросе или системе.

## 3. Структура проекта

```
src/
  index.ts            # registerRoot(RemotionRoot)
  Root.tsx            # регистрирует все композиции (<Composition/>)
  compositions/       # по одному файлу на графику
public/               # шрифты, изображения, звук (staticFile)
out/                  # готовые рендеры
remotion.config.ts    # общие настройки рендера

```

`remotion.config.ts` (для прозрачности важен PNG-imageformat):

```ts
import { Config } from "@remotion/cli/config";
Config.setVideoImageFormat("png");
Config.setOverwriteOutput(true);
```

## 4. Как создавать новую графику

1. Новый файл в `src/compositions/` — React-компонент анимации.
2. Зарегистрировать его в `src/Root.tsx` тегом `<Composition/>` (задать `id`, `width`,
   `height`, `fps`, `durationInFrames`, `schema`, `defaultProps`).
3. **Делай графику data-driven:** все тексты, цвета, числа, картинки выводи в пропы
   через `zod`-схему + `defaultProps`.

### Правило редактируемости в Studio (важное)

> Параметр появляется в правой панели Remotion Studio и доступен для правки **без кода**
> тогда и только тогда, когда он объявлен в `schema` как проп.
> Что зашито в код-константы — меняется только через код.

Поэтому всё, что пользователь захочет менять мышкой (тексты, цвета, тайминги, флаги),
**выводи в схему**. Списки (`z.array(z.object({...}))`) Studio показывает с
добавлением/удалением элементов.

## 5. Принципы анимации (делают результат «профессиональным»)

- **Полный вход И выход.** Каждый элемент появляется (из-за края или из `opacity: 0`),
  держится, затем уходит до конца клипа — ничего не «выскакивает» и не обрывается на
  середине движения. Это главное отличие аккуратной графики от любительской.
  (Если пользователь просит «обрыв ровно в конце» — оставляй вход, но убирай выход.)
- **Никакой линейщины.** Используй `spring` или eased-кривые (`interpolate` + easing);
  добавляй лёгкое «предвкушение» и небольшой overshoot с оседанием.
- **Каскад (stagger).** Элементы входят друг за другом на несколько кадров, а не разом.
- **Живость на удержании.** Пока графика «висит» — мягкий флоат, лёгкая пульсация свечения
  или медленный проход блика.
- **Читаемость.** Держи ключевой текст в title-safe (≈10% отступов), обеспечь контраст над
  видео (подложка/скрим/тень). Длинный текст ужимай/переноси, чтобы не вылезал за контейнер.
- **Тайминг под содержание.** Примерно секунда на короткую строку для чтения; общий
  хронометраж — в рамках запроса пользователя.

Технически анимация строится на **номере кадра**: `useCurrentFrame()`, `interpolate`,
`spring`, `Easing`. Не полагайся на CSS-анимации, привязанные ко времени (`animation: ...`) —
они не синхронизируются с покадровым рендером; переводи движение на кадры.

## 6. Прозрачность и экспорт

- **Полная сцена (непрозрачная):** MP4 (H.264).
  `remotion render <id> out/<id>.mp4 --codec=h264 --crf=18`
- **Оверлей с прозрачным фоном (альфа):** MOV, ProRes 4444.
  `remotion render <id> out/<id>.mov --codec=prores --prores-profile=4444 --pixel-format=yuva444p10le --image-format=png`
- **PNG-секвенция (напр. для CapCut):**
  `remotion render <id> out/png/frame-%04d.png --image-format=png`

> ⚠️ **MP4 / H.264 не хранит прозрачность.** Для альфы всегда бери **MOV ProRes 4444**
> (или PNG-секвенцию). В превью прозрачность выглядит как чёрное/шахматка — это норма,
> в файле там настоящий альфа-канал.

Для прозрачного фона композиция не должна иметь непрозрачной заливки на весь кадр
(корневой `AbsoluteFill` — без фонового цвета там, где нужна прозрачность).

### Приём «окно-маска» (по запросу)

Если нужен экран с заливкой, но с **прозрачным «окном»** внутри (чтобы в монтаже под него
подложить видео), вырежи в базовой заливке дыру через `clip-path: path(evenodd, "...")`
(внешний прямоугольник кадра + внутренний контур окна). Рендерить в MOV с альфой.

## 7. Remotion Studio (визуальный интерфейс)

- **Открывается в начале явной задачи по моушн-графике** (см. раздел «Начало задачи
  по моушн-графике»). При этом
  обязательно предупреди пользователя, что он там ничего делать не обязан — это для
  наглядности и контроля.
- Ручной запуск: `npm run studio` (или попроси Claude Code «запусти Studio»).
  Поднимется локальный сервер, обычно `http://localhost:3000`.
- Слева — список композиций, по центру — превью с проигрыванием, справа — пропы
  (редактируются вживую по правилу из раздела 4).
- **`remotion render` / `remotion still` окно НЕ открывают** — это headless-режим (только файл).
  Интерфейс появляется лишь при запуске `studio`.

## 8. Бренд / дизайн-система

В `ридэй` уже есть дизайн-система. Корневые `AGENTS.md`, UI kit и семантические
токены имеют приоритет. Для самостоятельной декоративной сцены допустима изолированная
палитра в её props или одном scene-local palette-файле; она не становится токенами UI.

- Для графики приложения используй существующие акцент, шрифт, скругления и правила
  контраста.
- Не публикуй рендер напрямую: передай утверждённый файл в основной content/vault
  pipeline по корневым правилам.
- Не помещай в Studio, Figma или примеры реальные личные данные без явной необходимости
  и соблюдения политики приватности проекта.

## 9. Заметки по рендеру

- Remotion при первом рендере скачивает headless-браузер — это норма.
- На macOS ниже 15 возможно предупреждение о версии ОС — на рендер обычно не влияет.
- Перед полным рендером полезно сделать `remotion still <id> out/preview.png --frame=<n>` и
  показать пользователю кадр на утверждение — быстрее, чем ждать весь клип.
