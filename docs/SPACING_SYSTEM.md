# Система отступов и близости

## Зачем она нужна

Эта система описывает **все продуктовые отступы** в календаре, шторках,
архиве, UI kit и Figma. Её цель — чтобы интерфейс читался группами, а не
набором случайных пикселей: пользователь сразу понимает, что относится друг к
другу, что является следующим блоком и где начинается новая секция.

Это не отдельный автономный агент. За системой постоянно следит существующий
**Design System Maintainer**: он читает этот документ перед задачами про UI,
раскладку или Figma, исправляет очевидные нарушения без изменения продуктового
смысла и не создаёт одноразовые значения.

## Три уровня

### 1. `spacing-primitives` — шкала

Примитивы — единственные числовые значения системы. Они не используются
непосредственно в продуктовых экранах и скрыты от публикации в Figma.

| Figma / CSS | Значение | Назначение |
| --- | ---: | --- |
| `space/text` / `--spacing-primitive-space-text` | 4px | плотная связь text label и значения |
| `space/inline` / `--spacing-primitive-space-inline` | 8px | иконка и label или другой компактный ряд |
| `space/stack` / `--spacing-primitive-space-stack` | 12px | компактный стек контента |
| `space/inset` / `--spacing-primitive-space-inset` | 16px | отдельный блок или стандартный inset |
| `space/group` / `--spacing-primitive-space-group` | 24px | граница между секциями |
| `space/section` / `--spacing-primitive-space-section` | 32px | крупный page-inset или просторная поверхность |
| `space/empty` / `--spacing-primitive-space-empty` | 48px | пустое состояние и намеренно свободная композиция |

### 2. `spacing-alias` — устойчивые решения

Aliases отделяют шкалу от смысла. Их тоже не связывают с обычными слоями в
Figma и не используют напрямую на продуктовых экранах.

| Alias | Значение | Когда использовать |
| --- | ---: | --- |
| `gap/text` | 4px | label и связанное с ним значение |
| `gap/inline` | 8px | иконка и label внутри контрола, короткий ряд |
| `gap/stack` | 12px | связанный вертикальный контентный стек |
| `inset/default` | 16px | стандартный внутренний padding и самостоятельный блок |
| `gap/group` | 24px | граница соседних секций |
| `inset/page` | 32px | крупный вертикальный page-inset или просторная поверхность |
| `inset/empty` | 48px | пространство вокруг empty state |

### 3. `spacing-semantic` — публичный контракт

Семантика — единственный слой, который применяют в коде и на обычных слоях
Figma. Имена читаемые, нижний регистр и kebab-case. CSS-переменные всегда
начинаются с `--spacing-semantic-`.

| Figma / CSS | Alias | Смысл |
| --- | --- | --- |
| `layout/page-gutter` / `--spacing-semantic-layout-page-gutter` | `inset/default` | постоянный боковой gutter мобильного экрана |
| `layout/inline-gap` / `--spacing-semantic-layout-inline-gap` | `gap/inline` | ряд из связанных элементов |
| `layout/content-gap` / `--spacing-semantic-layout-content-gap` | `gap/stack` | элементы одного контентного блока |
| `layout/block-gap` / `--spacing-semantic-layout-block-gap` | `inset/default` | соседние самостоятельные блоки |
| `layout/section-gap` / `--spacing-semantic-layout-section-gap` | `gap/group` | секции одной страницы |
| `layout/page-inset` / `--spacing-semantic-layout-page-inset` | `inset/page` | крупный вертикальный отступ страницы |
| `content/text-gap` / `--spacing-semantic-content-text-gap` | `gap/text` | text label и значение одной смысловой группы |
| `control/padding-inline` / `--spacing-semantic-control-padding-inline` | `inset/default` | горизонтальный padding контрола |
| `control/icon-gap` / `--spacing-semantic-control-icon-gap` | `gap/inline` | иконка и текст внутри контрола |
| `surface/padding` / `--spacing-semantic-surface-padding` | `inset/default` | обычный padding карточки/поверхности |
| `surface/padding-spacious` / `--spacing-semantic-surface-padding-spacious` | `gap/group` | просторная поверхность с большим объёмом контента |
| `empty-state/padding` / `--spacing-semantic-empty-state-padding` | `inset/empty` | внешний воздух вокруг пустого состояния |

## Правила близости

1. **Внутреннее и внешнее не смешиваются.** Компонент владеет своим внутренним
   padding и расстояниями между своими деталями; родитель владеет расстоянием
   между компонентами. Например, кнопка задаёт `control/icon-gap`, а footer
   задаёт расстояние между двумя кнопками.
2. **Внутреннее меньше внешнего.** В пределах одной группы используем 4–12px;
   следующий самостоятельный блок начинается как минимум с 16px. Переход к
   новой секции — 24px, большой page-inset — 32px, empty state — 48px.
3. **Одна группа — один wrapper.** Не добавлять отдельные `margin` к label,
   иконке и подписи, чтобы «на глаз» собрать группу. Нужен контейнер с
   `gap`, определённым семантической ролью.
4. **Не растягивать связанные элементы.** Иконка и подпись кнопки, код и его
   действие, заголовок и его подзаголовок остаются компактным кластером. Между
   ними не должно появляться пустое пространство из-за `space-between` или
   абсолютного позиционирования.
5. **Границы не заменяют и не отменяют близость.** Divider и обводка помогают
   разделить готовые группы, но не чинят неправильные gap или padding.
6. **Не создавать роль для одного экрана или дня.** Перед новой семантической
   ролью проверить существующие. Новая допустима только если описывает
   повторяемую потребность минимум двух контекстов и это невозможно выразить
   текущей ролью; причину фиксируют в этом документе и реестре токенов.

### Допустимые исключения

Сырые пиксели допустимы только для **art direction**, кадрирования медиа,
safe area и full-bleed. Это не продуктовый spacing. У такого правила рядом
обязателен комментарий вида:

```css
/* layout-exception: media crop follows the source artwork, not content rhythm. */
```

Исключение нельзя использовать, чтобы обойти токен ради одного дня, мема,
пузыря или карточки. Никогда не создавать day-specific spacing-переменные.

## Figma: коллекции, Scope и синхронизация

Машинный источник состава, значений, описаний, code syntax и правил
публикации — `design-tokens/spacing-contract.mjs`. Файл
`design-tokens/generated/spacing-variables.figma.json` — только его
генерируемый Figma-реестр. Этот документ описывает человеческие правила
близости и использования; он не заменяет машинный контракт.

| Коллекция | Что содержит | Публикация | Scope |
| --- | --- | --- | --- |
| `spacing-primitives` | FLOAT-примитивы `space/*` | скрыта | `[]` |
| `spacing-alias` | FLOAT aliases `gap/*`, `inset/*` | скрыта | `[]` |
| `spacing-semantic` | публичные FLOAT-роли из таблицы выше | опубликована | `[GAP]` |

- В Figma слои и компоненты привязываются только к
  `spacing-semantic`; примитивы и aliases — внутренняя инженерная шкала.
- У каждой переменной обязательны понятные description, значение/alias,
  scope, code syntax и `hiddenFromPublishing`. Для семантики code syntax
  повторяет CSS-переменную из таблицы.
- Синхронизация всегда идёт по порядку: primitive → alias → semantic. До
  объявления parity сверяются названия, количество, алиасы, значения,
  description, scope, code syntax и hidden/public flags.
- В Figma не создаются экранные или day-specific варианты вроде
  `day-29-gap` или `sheet-24-padding`.

`npm run audit:spacing` не даёт незаметно обойти эту систему: он проверяет
слои, метаданные Figma, свежесть реестра, отсутствие неиспользуемых внутренних
шагов и raw spacing без соседнего комментария `layout-exception`.

## Проверка перед handoff

Для изменения layout, компонента, календаря, шторки или spacing-токенов:

1. Проверить основной календарь, архив, типовую шторку и UI kit на 320px,
   390px и 430px ширины.
2. Убедиться, что safe areas сохранены, нет горизонтального overflow и ни
   один контрол не теряет touch target.
3. Проверить, что элементы одной группы ближе друг к другу, чем соседние
   группы; код и его CTA, текст и подпись, иконка и label не «слипаются» и не
   разъезжаются.
4. При Figma-изменении сверить три коллекции с кодовым/реестровым контрактом.
5. Выполнить обязательные проверки из `AGENTS.md` и
   `docs/QA_CHECKLIST.md`.

## Как развивать систему

Сначала подобрать существующую семантическую роль. Если она не подходит,
проверить, является ли отличие устойчивым паттерном, а не визуальной
особенностью одного сюрприза. Только затем добавить примитив (крайне редко),
alias и семантику в этой последовательности. Любая новая роль должна быть
понятной без знания номера дня.
