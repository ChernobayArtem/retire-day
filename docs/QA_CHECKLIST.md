# Чеклист перед релизом

Прогонять перед каждым пушем в `main`. Лучше всего — в **тест-режиме** (пароль `<TEST_PASSWORD_FROM_LOCAL_SECRET>`)
на реальном iPhone, плюс быстрый прогон в браузере на ширине 430px.

Тест-ссылки:
- `?date=2026-08-01` — старт (день 1 сегодня)
- `?date=2026-08-10` — годовщина
- `?date=2026-08-29` — финал
- `?date=2026-08-30` — постфинальный экран («Новая глава началась сегодня»)
- `?date=2026-09-03` — проверка humanized-duration («Уже 4 дня новой главы»)
- `?ui-kit=1` — внутренний каталог компонентов (только тестовая роль)

## UI kit

- [ ] Белая кнопка в шторке, архиве и постфинальном экране имеет одинаковую высоту, радиус, обводку и типографику.
- [ ] Иконка и подпись в кнопке визуально составляют одну группу; между ними нет растянутого пустого пространства.
- [ ] В новом или изменённом продуктовом layout используются только `--spacing-semantic-*`; исключение допустимо лишь для art direction, media crop, safe area или full-bleed и подписано комментарием `layout-exception`.
- [ ] Компонент владеет своим padding и внутренними gap, а его родитель — расстоянием до соседних компонентов. Внутренний зазор меньше внешнего; у одной группы нет «ручных» margin на её отдельных детях.
- [ ] Новой spacing-роли не создано ради одного экрана/дня: сначала переиспользована роль из `docs/SPACING_SYSTEM.md`.
- [ ] Проверены состояния `normal`, `pressed`, `focus-visible`, `disabled`, `loading` и ошибки поля.
- [ ] Каталог UI kit прокручивается на 320×667, 390×844, 430×780, 430×932 и 480×900.
- [ ] Боевая роль не может открыть `?ui-kit=1`; тестовая роль возвращается из каталога в приложение.

## Шторка дня (самое хрупкое место)

- [ ] Шторка выезжает **сверху**, одинаковой высоты для всех дней.
- [ ] **Заголовок** — одно слово/фраза, крупный, по центру.
- [ ] **Медиа-блок** корректный по типу: карточка-комплимент / коллаж / баннер+код / купон.
- [ ] Текст в **карточке-комплименте** отцентрирован по вертикали и горизонтали (не «уехал» вверх).
- [ ] **Пожелание** (серый текст) по центру, читается.
- [ ] **Мем-фото** нижним краем идёт ровно по нижней линии обводки (не висит в воздухе).
- [ ] Если день содержит **мем-фото и текстовый пузырь**, пузырь синий, стоит **вплотную слева от фото**; **хвостик направлен вправо — на лицо** (не в пустоту и не в обратную сторону). Внутри пузыря **нет эмодзи-сердечка**. Подпись помещается в 1–2 строки и не наезжает на фото. Если мем или пузырь не предусмотрены шаблоном дня, они не добавляются.
- [ ] **Дата** (дд.мм) снизу-слева, серая.
- [ ] Кнопки **«Предыдущий» / «Закрыть»** внизу; отступы вокруг кнопок = **16px со всех сторон** (снизу тоже 16, не больше).
- [ ] «Предыдущий» **задизейблен на дне 1**, активен на остальных и листает назад.
- [ ] «Закрыть» закрывает шторку.
- [ ] На 29-м дне link-кнопка **«Бонус»** расположена между подписью и мемом, не сдвигает остальные блоки и открывает бонусное видео.
- [ ] На 320px, 390px и 430px шторка сохраняет safe area, не имеет горизонтального overflow; связанные элементы (заголовок+подпись, код+действие, иконка+label) образуют компактные группы, а соседние блоки разделены заметнее.

## Интеракции

- [ ] **Копирование кода** сертификата: маленький тултип «скопировано» над иконкой, **ничего не появляется внизу** и вёрстка не прыгает.
- [ ] **Увеличение фото**: тап по коллажу открывает на весь экран; крестик или тап по тёмному фону закрывает **только фото**, шторка остаётся открытой.
- [ ] В полноэкранном фото работает pinch двумя пальцами в диапазоне 1×–4×, увеличенное фото двигается одним пальцем, двойной тап приближает/сбрасывает масштаб.
- [ ] После pinch/pan фото случайно не закрывается; крестик и `Escape` закрывают только просмотр фото, масштаб страницы PWA остаётся заблокированным.
- [ ] Кнопка скачивания появляется только в полноэкранном просмотре фото/коллажа и сохраняет именно открытое изображение.
- [ ] Видео открывается поверх всей шторки: заголовок, мем, дата и нижние кнопки не просвечивают и не перекрывают плеер; только в этом режиме видны кнопки скачивания и закрытия.
- [ ] Открытие/закрытие шторки без визуальных рывков.

## Главный экран / календарь

- [ ] Экран **не скроллится** (нет резинового оверскролла), помещается целиком.
- [ ] Прогресс-бар из орхидей + процент, отсчёт слева, дата справа.
- [ ] Ячейки: прошедшие — розовые, сегодня — белая с рамкой, будущие — серые.
- [ ] Логотипы стоят на своих днях: Ozon=3, WB=11, Золотое яблоко=19, Lamoda=23; день 28 использует собственную иллюстрацию.
- [ ] Календарь заканчивается на 29-м (без 30–31).
- [ ] На 320px, 390px и 430px календарь не получает горизонтальный overflow, сохраняет боковой gutter и не накладывается на safe area.

## После 29 августа

- [ ] 29 августа ещё показывает финальный календарный экран; новая глава начинается только 30-го.
- [ ] 30 августа — «Новая глава началась сегодня»; дальше период идёт в днях, неделях, календарных месяцах, а после года — в годах и месяцах.
- [ ] `Случайный сюрприз` открывает обычную шторку одного из 29 дней; закрытие возвращает в эпилог.
- [ ] `Все воспоминания` открывает архив со всеми 29 днями; `Назад` возвращает в эпилог.
- [ ] Рассвет помещается на высотах 667–932 px; при `prefers-reduced-motion` движение отключено.

## Деплой / приватность / шифрование

- [ ] `npm run verify:release` без ошибок: сборка, цветовые/WCAG-проверки, полная расшифровка и сверка vault с локальными источниками, локальный поиск случайно раскрытых данных и повторная проверка готового `dist/`.
- [ ] Локальная папка `local-content/` не попала в коммит.
- [ ] **После правки контента или любого личного медиа — `npm run encrypt`** и включить обновлённый `public/vault/` в следующий разрешённый пользователем коммит.
      (CI не может шифровать — у него нет `local-content/`; в репозиторий едет готовый сейф.)
- [ ] В собранном бандле/репозитории **нет** текстов-сюрпризов, кодов, паролей и личных фото
      (`npm run audit:sensitive` проверяет реальные локальные значения, но никогда не печатает их в отчёте).
- [ ] Публичные ассеты (логотипы брендов, котёнок, баннер Ozon, иконки) — намеренно не шифруются.

### Как устроен сейф (напоминалка)
- Актуальный плейнтекст лежит только в `local-content/current/`, а ключи и пароли —
  в `local-content/credentials/`; вся папка локальная и находится в gitignore.
- `npm run encrypt` шифрует всё в `public/vault/` (`content.bin` + `media/*.bin` + `manifest.json`).
- Пароль расшифровывает ключ контента (envelope для обоих паролей). Ключ хранится на устройстве —
  Лера вводит пароль один раз. Реальные пароли не копируются в документацию и проверяются только локальным redacted-аудитом.
