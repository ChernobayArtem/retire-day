# Чеклист перед релизом

Прогонять перед каждым пушем в `main`. Лучше всего — в **тест-режиме** (пароль `<TEST_PASSWORD_FROM_LOCAL_SECRET>`)
на реальном iPhone, плюс быстрый прогон в браузере на ширине 430px.

Тест-ссылки:
- `?date=2026-08-01` — старт (день 1 сегодня)
- `?date=2026-08-10` — годовщина
- `?date=2026-08-29` — финал
- `?date=2026-08-30` — постфинальный экран (день 1 новой главы)
- `?date=2026-09-03` — проверка продолжения счётчика (день 5)

## Шторка дня (самое хрупкое место)

- [ ] Шторка выезжает **сверху**, одинаковой высоты для всех дней.
- [ ] **Заголовок** — одно слово/фраза, крупный, по центру.
- [ ] **Медиа-блок** корректный по типу: карточка-комплимент / коллаж / баннер+код / купон.
- [ ] Текст в **карточке-комплименте** отцентрирован по вертикали и горизонтали (не «уехал» вверх).
- [ ] **Пожелание** (серый текст) по центру, читается.
- [ ] **Мем-фото** нижним краем идёт ровно по нижней линии обводки (не висит в воздухе).
- [ ] **Пузырь-мем**: синий, стоит **вплотную слева от фото**; **хвостик направлен вправо — на лицо** (не в пустоту и не в обратную сторону). Внутри пузыря **нет эмодзи-сердечка**. Подпись помещается в 1–2 строки и не наезжает на фото. Проверять на всех новых днях с мемом (ширина фото разная).
- [ ] **Дата** (дд.мм) снизу-слева, серая.
- [ ] Кнопки **«Предыдущий день» / «Закрыть шторку»** внизу; отступы вокруг кнопок = **16px со всех сторон** (снизу тоже 16, не больше).
- [ ] «Предыдущий день» **задизейблен на дне 1**, активен на остальных и листает назад.
- [ ] «Закрыть шторку» закрывает шторку.

## Интеракции

- [ ] **Копирование кода** сертификата: маленький тултип «скопировано» над иконкой, **ничего не появляется внизу** и вёрстка не прыгает.
- [ ] **Увеличение фото**: тап по коллажу открывает на весь экран; тап по фото закрывает **только фото**, шторка остаётся открытой.
- [ ] Открытие/закрытие шторки без визуальных рывков.

## Главный экран / календарь

- [ ] Экран **не скроллится** (нет резинового оверскролла), помещается целиком.
- [ ] Прогресс-бар из орхидей + процент, отсчёт слева, дата справа.
- [ ] Ячейки: прошедшие — розовые, сегодня — белая с рамкой, будущие — серые.
- [ ] Логотипы стоят на своих днях: Ozon=3, WB=14, Золотое яблоко=24, лого Леры=29.
- [ ] Календарь заканчивается на 29-м (без 30–31).

## После 29 августа

- [ ] 29 августа ещё показывает финальный календарный экран; новая глава начинается только 30-го.
- [ ] 30 августа — `1-й день`, дальше счётчик продолжается без обнуления в сентябре.
- [ ] `Случайный сюрприз` открывает обычную шторку одного из 29 дней; закрытие возвращает в эпилог.
- [ ] `Все воспоминания` открывает архив со всеми 29 днями; `Назад` возвращает в эпилог.
- [ ] Рассвет помещается на высотах 667–932 px; при `prefers-reduced-motion` движение отключено.

- [ ] Ставится на домашний экран (Safari → Поделиться → На экран «Домой»).
- [ ] Открывается без адресной строки (standalone), контент не лезет под чёлку.
- [ ] Иконка на домашнем экране — цветок, не скриншот страницы.
- [ ] После нового деплоя приложение подхватывает свежую версию (не залипает на старой).
- [ ] Дата/отсчёт совпадают с реальной датой телефона.

## Деплой / приватность / шифрование

- [ ] `npm run typecheck` и `npm run build` без ошибок.
- [ ] Оригиналы (`days/`, `элементы из фигмы/`, `secret/`) не попали в коммит.
- [ ] **После правки контента или фото — `npm run encrypt`** и закоммитить обновлённый `public/vault/`.
      (CI не может шифровать — у него нет `secret/`; в репозиторий едет готовый сейф.)
- [ ] В собранном бандле/репозитории **нет** текстов-сюрпризов, кодов, паролей и личных фото
      (быстрый чек: `grep -r "пюрешку\|99N6" dist` → пусто; старый путь фото на проде → 404).
- [ ] Публичные ассеты (логотипы брендов, котёнок, баннер Ozon, иконки) — намеренно не шифруются.

### Как устроен сейф (напоминалка)
- Плейнтекст лежит только в `secret/` (контент `content.mjs`, пароли `passwords.json`) — локально, в gitignore.
- `npm run encrypt` шифрует всё в `public/vault/` (`content.bin` + `media/*.bin` + `manifest.json`).
- Пароль расшифровывает ключ контента (envelope для обоих паролей). Ключ хранится на устройстве —
  Лера вводит пароль один раз. `<TEST_PASSWORD_FROM_LOCAL_SECRET>` — короткий, поэтому это защита от «случайно наткнулся», не от целевого взлома;
  для крепости можно сделать тест-пароль длиннее.
